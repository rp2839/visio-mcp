**Verdict: accept, with one blocking correction and three small precision edits.**

## The two refinements: both accepted
- **Group rotation by delta.** `rotate <id> by=<degrees>` takes an optional pivot, and `angle=` on a group is rejected with guidance (`editor-and-commands.md:213-217`). Because a group's orientation is normalised to zero, an absolute angle on a group has no stable meaning, so this is the right choice. Keeping `angle=` absolute for shape/text/image preserves the source syntax. The structured operation matches (`editor-and-commands.md:99-106`).
- **`asset:<slug>~<full-sha256>`.** I accept this in place of my 12-character suggestion. It removes the collision class entirely, and the ID is generated by the engine and returned in the result, so its length costs nothing. Bare-slug resolution and explicit library scope are both specified (`host-and-interoperability.md:266-268`).

## Blocking contradiction (one)
**B1 — the admission-time `baseRevision` check breaks R2's post-commit retry.**
- `architecture.md:139` says "At admission and queue head, recheck document/session and baseRevision".
- `host-and-interoperability.md:87-88` says "Recheck scope/revision on admission and at queue head".

Take a retry that arrives after its original has committed. Its `baseRevision` is now stale. If it's held at the gesture gate and then admitted, the admission check rejects it with `revision_conflict` before it ever reaches the transaction-cache lookup at the queue head. That contradicts `editor-and-commands.md:119-121` ("This order is mandatory for post-commit retries").

Fix: admission rechecks **session/document only**. The `baseRevision` check happens only at the queue head, after the cache lookup.
- `architecture.md:139`: "On admission recheck document/session; at the queue head verify session/document, check the transaction cache, then check baseRevision."
- `host-and-interoperability.md:87`: "Recheck scope on admission; at queue head apply scope → transaction cache → baseRevision."

## Precision edits (non-blocking)
1. **Name the structured rotate fields** (`editor-and-commands.md:59-60, 99`). The text says "angular delta" but never names the field. Specify, for example, `rotate{targets, angleDeg}` as absolute (shape/text/image only) and `rotate{targets, deltaDeg, pivot?}` as relative.
   - A group target with `angleDeg` is rejected as `invalid_request` with `details.reason:"group_rotation_requires_delta"`.
   - Either reject a single rotate that mixes absolute and delta forms, or state that `deltaDeg` applies to every target.
   - Apply the same rule to the DrawScript `by=` form on non-group targets: either allow it or reject it explicitly.
2. **Retry wording** (`architecture.md:113-115`). "Reconcile state/history" still over-promises after a session change. Align it with `host-and-interoperability.md:64-66`: "within the same session, reconcile via get_changes transactionIds; after a session change, by current state only."
3. **Pivot on a single-element rotate.** If the structured rotate accepts `pivot` for shape/text/image targets, define it as an orbit plus a rotation change. Otherwise reject `pivot` on non-group targets. As written it's unspecified.
